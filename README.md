# بوابة نتائج جامعة اللاذقية — نسخة Firebase

## تم تعديل نظام الاعتراضات
- تقديم الاعتراض يحفظ مباشرة في **Cloud Firestore** ضمن collection اسمها `appeals`.
- متابعة الاعتراض تقرأ الطلب من Firestore.
- لوحة التحكم تقرأ جميع الطلبات من Firestore.
- تغيير الحالة من «قيد المراجعة» إلى «تمت المراجعة / مقبول / مرفوض» يُحفظ دائماً في قاعدة البيانات.
- ملاحظة الإدارة تُحفظ وتظهر للطالب عند متابعة الطلب.
- لم يعد نظام الاعتراضات يعتمد على SQLite أو `server.py`.

## التشغيل
يمكنك تشغيل الموقع عبر Live Server أو أي استضافة ملفات ثابتة:
- `index.html` لموقع الطلاب.
- `admin.html` للوحة التحكم.

## مهم جداً — Firestore Rules
الملف `firestore.rules` يحتوي قواعد بسيطة حتى يعمل الموقع فوراً. هذه القواعد **ليست حماية إدارية حقيقية** لأنها تسمح بالقراءة والتعديل من جهة العميل.

إذا كان الموقع سيُنشر للعامة، يجب إضافة Firebase Authentication وربط قواعد Firestore بحساب الإدارة قبل الاعتماد عليه كنظام إداري حقيقي.

## Firebase
تم وضع إعدادات مشروع Firebase التي أرسلتها في `config.js`.


## 🔐 إعداد قفل لوحة الإدارة

1. من Firebase Console افتح مشروع `lattakia-uni`.
2. افتح **Authentication → Sign-in method** وفَعّل **Email/Password**.
3. من **Authentication → Users** أنشئ حساباً إدارياً واحداً لك فقط (بريد + كلمة مرور).
4. افتح **Firestore Database → Rules** وانسخ محتوى ملف `firestore.rules` الموجود هنا ثم اضغط Publish.
5. افتح `admin.html`؛ لن تظهر لوحة التحكم إلا بعد تسجيل الدخول بالحساب الإداري.

## 🚪 قفل باب الاعتراضات لاحقاً

حالياً باب الاعتراضات **مفتوح** كما طلبت.

افتح `config.js` وابحث عن:

`const APPEALS_ENABLED = true;`

عندما تريد إغلاق الباب غيّرها فقط إلى:

`const APPEALS_ENABLED = false;`

وعندها تظهر للطالب رسالة أن باب الاعتراضات مغلق، ولا يمكنه الإرسال. ولإعادة الفتح أعدها إلى `true`.

## 🚫 منع أكثر من اعتراض للطالب

النظام يتحقق من وجود أي طلب سابق بنفس رقم الاكتتاب قبل الحفظ. إذا وجد طلباً سابقاً يظهر للطالب:

**«لديك طلب اعتراض سابق للتعديل، يرجى مراجعة شؤون الطلبة»**

كما أن إنشاء الطلب يستخدم معرفاً ثابتاً للطالب لمنع تكرار الطلب عند الضغط السريع على زر الإرسال.

## 💾 تعديل حالة الاعتراض

لوحة الإدارة تستخدم Firebase Authentication للحماية، وتعديل حالة الطلب يتم مباشرة في Firestore. لذلك زر **حفظ التعديل** يحفظ الحالة وملاحظة الإدارة بشكل دائم.
